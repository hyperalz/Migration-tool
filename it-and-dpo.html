What MapBridge reads and stores

✓ Reads

Field names (like employee_id or start_date), field types (like number or date), allowed values (like Y and N), and field notes from your supplier.

✗ The connector never reads

Employee names, salaries, addresses, or any other personal data. The read-only tool for SQL Server and Oracle only queries the system catalog (the list of tables and fields), not the tables themselves.

The one exception: comparing test loads (reconciliation)

Reconciliation is an optional step that compares an extract from the old system with one from the new system. Those extract files contain real records. They are opened in the web browser of the person running the check, on their own computer. The rows are not saved and are not sent to us or to any server. No AI is involved in this step.

What is kept afterwards is the result: counts, totals, record keys and a few example values for each difference found. Fields marked as personal show dots in place of the value. MapBridge ticks these automatically for names, contact and bank details, identifiers such as UPN and NHS numbers, titles, and special category and sensitive data such as health, religion, sexual orientation, SEN, free school meals and safeguarding. The person running the check can change any of them. Because record keys are kept, the result should be handled as personal data.

Where it is stored

In the web browser on your computer. Not on a server. When you close the browser, it stays on your computer unless you clear your browser data.

What the AI suggestion mode sends

If you use the built-in matcher

Nothing is sent anywhere. It runs entirely in your web browser.

If you use your own AI API key

Only field names, types, and notes are sent to the AI service you choose (like OpenAI or Azure). No employee names, salaries, or any personal data.

If you read screenshots of the old system

Each screenshot is shrunk in your browser and sent to the AI service you choose, which returns the labels it can see. Only the text results are kept; the images are not stored. Screenshots can show personal data, so use blank or test records.

Your API key stays in your web browser and is only sent to the AI service you choose. It is never sent to us. Unless you tick "Remember the key on this computer", it is forgotten when you close the browser window.

The read-only connector

A Python script that your IT team runs inside your network for the duration of the migration, then deletes.

What it does

Queries information_schema or system catalogs to get table and column names, types, and constraints.

Writes a JSON file with the list of fields.

What it needs

SQL Server: A read-only database user with VIEW DEFINITION permission.

Oracle: A user with SELECT on ALL_TABLES, ALL_TAB_COLUMNS.

What it never does

Query user tables. Read employee names, salaries or other personal data. Send data anywhere. Listen on a port.

Ready field lists

MapBridge can start a project from a ready list of a system's fields, instead of a blank page.

  • A ready list holds field names, types, whether a field is needed, and short notes. Never data.
  • Each list says where it came from (a public standard, a supplier's public documentation, or the supplier itself) and when it was checked. The evidence pack records which list a project used.
  • We write the notes ourselves. We do not copy suppliers' files or help text.
  • A council's own field list is only reused for other projects with the council's written permission, and only where its supplier contract allows it.

Security in this version

MapBridge runs entirely in the web browser, with no MapBridge server or database. This is how it is protected, and what it does not do yet.

In place

  • Hosted as plain files on GitHub Pages, always over HTTPS.
  • A content security policy: pages can only run MapBridge's own code and two libraries from fixed addresses. Each library is checked against a known fingerprint before it runs. There are no inline scripts.
  • Passwords are never stored. Each account keeps a salted hash (PBKDF2 with SHA-256, 150,000 rounds) made by the browser's own cryptography.
  • Your AI key is only sent to the AI address you choose, and is forgotten when you close the window unless you ask MapBridge to remember it.
  • A warning, and a box to tick, before any screenshot is sent to an AI service.
  • No analytics, tracking or advertising, and no cookies.

Not yet

  • Accounts and projects belong to one web browser. Anyone who can use that browser can open them, so use a computer account that only you use.
  • No shared workspace, single sign-on or record of who viewed what. These come with the hosted version.
  • No independent security test or certification yet.
  • Do not keep real personal data in this version beyond what the optional file comparison needs.

Data protection impact assessment

Questions DPOs ask and our answers.

What personal data does MapBridge process?

For field matching and sign-off: none. MapBridge works from field names, field types, allowed values, and field descriptions.

The optional step that compares test loads is different. It opens extract files that contain real records, in the browser of the person running the check. Rows are not saved or sent anywhere. The stored result holds counts, totals, record keys and a few example values, with fields marked as personal masked. Treat that result as personal data, and decide who in your organisation runs this step.

Where is the data stored?

In the web browser on the user's computer, using browser localStorage. No data is sent to a server or stored in the cloud.

Who has access to the data?

Only the person using that web browser. There is no server, no database, and no shared workspace in the current version.

What happens to the data after the migration?

It stays in the browser unless the user clears their browser data. We recommend exporting the final signed-off report as a PDF or CSV, then clearing the browser data.

Does the AI mode send personal data?

Matching suggestions send only field names, types and notes, never records. Reading screenshots is different: each picture is sent to the AI service you choose, so a screenshot that shows a real person sends their details too. MapBridge warns about this and asks the user to confirm before any picture is sent. Use blank screens or test records, or a model that runs on your own computer. Both AI features are optional and use your own key.

What permissions does the read-only connector need?

SQL Server: VIEW DEFINITION on the database. Oracle: SELECT on ALL_TABLES, ALL_TAB_COLUMNS, ALL_CONSTRAINTS. It queries the system catalog only, never user tables.
