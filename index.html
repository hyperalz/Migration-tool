How a migration project works

Built for the real pattern: an LA, a target system supplier, and a delivery partner all need the same mapping truth — without another spreadsheet.

1

Create & invite

Sign in, create a project, invite the other party by email. Role-based access from day one.

2

Upload schemas

JSON or CSV upload. Schema metadata only — table names, columns, types, lookups. Live connectors are on the roadmap.

3

Map visually

Drag arrows between columns. Add transforms, lookup rules, and service area groupings.

4

Test & live checks

Record SQL sent, test upload, checks, live push, and sign-off — per column, with names and timestamps.

✓SQL sent ✓Test +Live Done
5

Export & close

Download mappings plus full traceability log. Close the project — all data permanently deleted.

Built for migration pain, not generic ETL

The spreadsheet master document problem — unmapped fields, lookup conversions, and "not convinced this was sent to test" — is what this replaces.

✓

Test & live traceability

Per-column pipeline from SQL sent through test checks, live push, and sign-off. Click to record, revert with history kept.

👤

Who did what

Migration team roster. Every step records who checked — including resends, failures, and reverts — with timestamps.

⚡

Lookup & transform rules

Capture Synergy → Impulse code conversions, defaults, and join conditions on each mapping line.

📊

Live dashboard

Pipeline completion, status mix, service area progress, and audit activity — updated as your team records steps.

↔

Visual column mapping

Side-by-side schemas with drag-and-drop lines. Unmapped and type-mismatch columns flagged instantly.

📤

Exportable artefacts

Excel or JSON with mappings, verification status, traceability columns, and full audit history.

Data privacy

In this version, all data is stored in your browser's local storage only. No server, no backend.

Browser-only storage (current version)

All schemas, mappings, and project data are stored in your browser's localStorage. Nothing is sent to a server. Clear your browser data to permanently delete. Export your work before doing so.

Roadmap: Server-backed lifecycle

Planned: project-scoped workspaces with secure authentication, invite-based access, and a delete-on-completion workflow. When a migration completes, you'll export the mapping package and trigger permanent deletion.

Roadmap: Metadata-only connectors

Planned: connectors pull table and column definitions, types, and lookup structures from source systems. No pupil records required for the mapping layer.

Audit trail while active

Append-only history per column while the project is open — every check, resend, and revert logged with who and when. In the current browser version, audit logs are kept in local storage.
